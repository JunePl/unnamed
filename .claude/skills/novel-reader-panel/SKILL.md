# 虚拟读者团审读流程

**Why：** 作者和改稿者都已经知道答案，所以永远读不出"第一次读"的感受。这个 skill 用**上下文隔离的独立读者**还原首读体验——他们不知道设定、不知道伏笔、不知道作者想干什么，只有正文写出来的东西。**读者读不到的，就等于没写。**

**触发条件**：用户要求"读者团审读／盲评／审读报告／看看读者怎么想"，或一卷完稿、大修收官、上架前验收。

---

## 输入参数

- **评审对象**：默认 `正文/正文.novel` 全文；可指定章节区间（未完成的章节不计入评分，但要在报告里标注）
- **审次**：初审／N 审。N 审必须做**二审对照**（与上一份报告逐维对比：修复是否兑现、有没有引入新事故）
- **人数**：默认 12 人，可增减

---

## Step -1 — ⛔ 隔离环境准备（2026-09-02 五审后新增，不许跳过）

**Why：** 五审做过一次实证审计，结论是**声明式禁读根本无效**。读者 subagent 在动用任何工具之前，上下文里就已经被注入了四样东西，指令删不掉：

| 通道 | 注入内容 | 危害 |
|---|---|---|
| 项目 `CLAUDE.md` | 全文，含「短句不得占比大于 8%」等**带数值的评分标尺**与反例原句 | 读者按作者自己的美学打分，不是按陌生读者的体感 |
| `MEMORY.md` | 记忆索引全文，含「四轮盲评」「报告在 Project/Logs/」及通往剧透文件的路径 | 读者知道这是第 N 轮、知道前几轮扣过分 |
| **`gitStatus` 快照** | **工作区全部文件名**（含未跟踪） | **最毒。文件名本身即剧透** |
| skills 列表 | `novel-reader-panel` / `novel-rewrite` 的名称与描述 | 读者知道自己在干什么、知道产出模板 |

五审实测泄漏的文件名示例（全部只靠文件名就说破了谜底）：
`画商案真相层_空窗与老彼得落子`（凶手身份＋诡计名词）、`阿尔温预视能力线_机制梳理`（主角有预视能力）、`画商案真相层_V4十七层`（真相 17 层）、`第一卷V13.0_119章细纲`（第一卷共 119 章）。

⚠️ **gitStatus 是主会话启动时的快照**——在同一会话内修改 git 状态**不会**更新它。

### 唯一可靠做法：项目外干净目录 ＋ 独立会话

```bash
ISO="/tmp/br-$(date +%s)-$RANDOM"          # 路径中性，不含项目名
mkdir -p "$ISO"
cp <正文路径> "$ISO/manuscript.txt"          # 文件名中性，去掉「正文」「novel」字样
# 把任务书与 12 画像写入 "$ISO/TASK.md"
```
该目录：**无 `.claude/CLAUDE.md`、非 git 仓库、不绑定本项目 memory、不加载 `novel-*` skills**——四条通道一次断干净。
然后 **`cd "$ISO"` 并在那里启动一个新会话**执行 TASK.md。**不要在项目目录里跑读者团。**

### 退而求其次（做不到新会话时）
必须在报告中显著标注「**本轮存在已知上下文泄漏**」，并对下列结论一律打折：推理轨迹与「第几章锁定某角色」、文笔维度、任何与被泄漏文件名相关的判断。
**同时开跑前先把工作区未跟踪的剧透文件提交掉**（下一次会话的快照才会干净）。

## Step 0 — 生态调研（必须先于阅读）

⛔ **不许跳过，也不许凭记忆写。** 读者偏好逐年变，用 WebSearch 查**当前年份**的实际数据。

四路 + 行业面，各出一份摘要：

| 路 | 要查什么 |
|---|---|
| 起点付费端 | 黄金三章留存现状、节奏共识（多少字一个高潮）、弃书原因 TOP、当红题材与均订标杆 |
| 晋江端 | 人设/OOC 容忍度、情绪钩子密度、文笔与辞藻的分野、当年关键词 |
| NGA／龙空老白向 | 逻辑自洽与智商在线的判定标准、最恨的毛病（文青病/降智/装逼打脸） |
| 轻小说文库系 | 角色魅力优先级、萌点可记忆性、对话比重、忌讳 |
| 行业面 | 用户规模与年龄结构、新增用户画像、题材风向升降 |

**每路摘要末尾必须写一句「赛道口碑规律」**——这一条是后面所有评分的锚。

### 0.1 维度增补检查（这一步决定报告有没有落后）

把调研结果与**上一份报告的评分维度**逐条对照，问三个问题：

1. 今年出现了上一版没有的**新毒点**吗？（例：AI 量产文涌入 → 加「AI味」维度；推理读者集体要求可参与破案 → 加「智商在线」维度）
2. 上一版的某个维度**今年已经不重要**了吗？
3. 有没有新的**弃书触发器**要写进读者的行为约束里？

历史沿革（继承，别丢）：
- 基础 8 维：开篇／人物／世界观／悬念／节奏／文笔／情绪爽感／可读性
- 二审增补：**AI味**（判"人写/机写"，真人毛边是资产，别抛光成规范文）
- 三审增补：**智商在线**（＋全员推理严苛指令）

## Step 2 — ⭐ 人类式独立阅读（本 skill 的核心）

### 2.1 隔离机制（硬要求）

**每位读者必须是一个独立的 subagent**，用 Agent 工具并行启动。原因：只有上下文隔离，才不会互相污染，也不会共享"我已经知道答案"的记忆。

每个 subagent 的可见范围：
- ✅ **隔离区里的 `manuscript.txt`（见 Step -1）**，或指定区间
- ⛔ **设定集、Cases、CHANGELOG、CLAUDE.md、大纲、细纲、memory、上一份审读报告——一律禁读**
- ⛔ 不许 grep 关键词去"查证"某个伏笔埋在哪
- ⛔ 不许知道其他读者的结论

> 🟥 **上面这几条「禁读」只挡得住主动检索，挡不住被动注入。** 被动注入必须靠 Step -1 的物理隔离解决。**只写禁读条款而不做物理隔离＝没有隔离。**

### 2.1b ⛔ prompt 本身不许泄漏（五审最大教训）

五审的污染**主要来自汇总方写的 prompt，而非继承**。实际发生过的四起：
- 周老师的 prompt 里**直接写进了上一轮结论的证据原文**（「我两周前就收到过委托」「这是我自己取的指印」）→ 他"发现"的事故是被告知的
- 小飞的 prompt 里写了「别人代他报仇＝零分」→ 精确预告了本作的病
- 考据君的 prompt 里写了「突然换名字导致认不出＝最高优先级事故」→ 上一轮的结论
- 柠檬茶的 prompt 里抄了**项目 CLAUDE.md 的短句反例** → 把作者的标尺塞进了读者的审美

**规则**：画像只写**性格与关注类别**（「他在乎公平推理」），**绝不写具体事故、具体行号、具体原文、任何数值标尺**。凡是上一轮报告里出现过的具体结论，一律不得进入 prompt。

### 2.2 🟥 人类阅读铁律（写进每个 subagent 的 prompt）

**你是一个人，不是一台检索机器。请严格按人类的方式读：**

1. **顺读，不跳读，不检索。** 从第一章第一行读到最后，不许倒回去查"这个名字前面出现过吗"。**读到哪一章就只知道那一章为止的信息。**
2. **记不住就是记不住。** 生僻人名、数值、机制，第一次出现时你多半记不牢；第二次出现如果没有提示，你就是想不起来他是谁——**照实记录"我这里没认出来"**，这是最有价值的反馈。
3. **会走神。** 大段景物、设定讲解、重复的流程，你会跳着看。跳过了就照实说跳过了。
4. **情绪是连续的。** 上一章的疲劳、憋屈、无聊会带到下一章。不许每章重置心情。
5. **会预判、会猜。** 读到疑点就猜凶手、猜身份、猜伏笔。**记录你在第几章猜到了什么、后来对不对**——猜太早说明泄底，全程猜不到说明线索没给。
6. **会在某一章合上书。** 一旦你想弃书，**记下章号和那一刻的原因**，然后（为了完成任务）继续读，但后面的评分要带上"我本来已经弃了"的心情。
7. **只看写出来的。** 作者心里的设定、后面会解释的、别处有档案的——**都不算**。你读不到就是没有。
8. **不做文本分析。** 不许输出"此处运用了对比手法"。你要说的是"这里我出戏了""这段我看不懂""这个人我讨厌"。

### 2.3 每位读者的产出格式

```
【读者代号】

## 0. 先验自报（必填，必须是第一项）
- 在读第一行之前，我对这本书已经知道的任何信息：（逐条列；确实一无所知则写"无"）
- 我读过的文件清单：（全部路径）
- 我是否曾读取或探查稿件以外的内容：是/否

- 八维（或当次维度表）打分，每项 1–10，附一句理由
- 追至百万字概率：__%
- 愿意付费阅读概率：__%
- 弃书点：第__章，原因；（若多次想弃，全部列出）
- 我在第几章猜到了什么：（推理轨迹，含猜错的）
- 认不出来的人／看不懂的地方：（章号＋原文片段）
- 我跳过了哪些段落
- 最好的三处（章号＋为什么）
- 最差的三处（章号＋为什么）
- 一句话总评
```

**姚编额外产出**：商业评级（S/A/B+/B/C）、前三章留存预估、能不能签、要改什么才能签。

## Step 3 — 交叉汇总

主 agent 收齐 12 份独立报告后汇总，**不许改写读者的结论**，只做归并：

1. **评分矩阵**：12人 × 各维度 ＋ 均分；标出最高分维度（承重柱）与最低分维度（出血口）
2. **弃书点地图**：哪一章流失哪些读者、病因分类（慢／憋屈／调性崩／看不懂／逻辑崩）
3. **共识结论**：
   - **命根子**：≥8 人好评的，改稿时必须保住
   - **S 级**：≥8 人点名的一致性硬伤（错字、数值、时间线、复读段）
   - **A 级**：结构与节奏（弃书直接原因）
   - **B 级**：调性分歧区（按目标读者取舍，标明哪派要哪派不要）
4. **推理参与度汇总**（若有推理线）：几人在第几章猜对了什么／几人全程没猜到／有没有"主角掌握了读者不知道的信息就动用"的毒点
5. **N 审对照**：与上一份报告逐维对比，标注 ✅已兑现 ／ ⚠️未兑现 ／ 🆕新引入

---

## Step 4 — 最终裁定

报告末尾必须给三个数，并写清算法依据：

- **追至百万字存活率**＝12 人概率均值（附分布：谁最高谁最低、为什么）
- **付费阅读概率**＝12 人愿付费均值（付费端与免费端分开说）
- **商业评级**＝姚编评级 ＋ 一句话理由

三个数**不许拍脑袋**，必须由读者各自的数值汇总而来。

## Step 5 — 落盘与修改清单

报告写到 `Project/Logs/读者团审读报告_<YYYY-MM-DD>.md`，结构：

```
# 读者团审读报告（日期）
> 评审对象 / 方法 / 一句话结论
一、生态调研摘要（四路＋行业面＋赛道口碑规律）
二、评分矩阵
三、弃书点地图
四、共识结论（命根子／S／A／B）
五、推理参与度（如适用）
六、N审对照（如适用）
七、章节级修改清单（P0一致性／P1开篇／P2中段／P3调性，每条带行号）
八、最终裁定（存活率／付费概率／商业评级）
```

**修改清单每条必须带行号**，否则无法执行。

同步：
- `Project/CHANGELOG.md` 加一条
- memory 更新（结论、分数对照、报告路径）

## 红线

1. ❌ 跳过生态调研，或凭记忆写调研
2. ❌ 读者共享上下文（必须独立 subagent）
3. ❌ 读者读了设定集／大纲／旧报告／memory
4. ❌ 读者用 grep 检索去"验证"伏笔（人类读者不会这么读）
5. ❌ 读者做文本分析而不是说阅读感受
6. ❌ 汇总时替读者改结论、和稀泥、把负面评价洗成中性
7. ❌ 最终三个数拍脑袋给，不由读者数据汇总
8. ❌ 修改清单不带行号
9. ❌ N 审不做与上一审的逐维对照
10. ❌ **在项目目录里跑读者团**（＝四条注入通道全开，见 Step -1）
11. ❌ **prompt 里预置具体事故、行号、原文或评分标尺**（见 2.1b）
12. ❌ **把 prompt 里给过的指引，当成读者的独立发现写进报告**
13. ❌ **读者证词里的频次断言（「连续三次」「每章都」「三遍」）未经 grep 核实就写进报告**——五审踩过：柠檬茶「三次摘下眼镜【未检测到真灵】」经核实不成立（该读数全书仅 6 处、5 处在第 1 章一次全员扫描内；取镜动作在第 2/3/**10** 章；第 4 章正文明写「他没摘眼镜」），汇总方未核即据此开出修改条目。**读者的体感数据有效，但他归因的机制可能是记忆合成。**
